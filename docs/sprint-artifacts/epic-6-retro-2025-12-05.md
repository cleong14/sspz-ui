## Technical Implementation Notes

### Key Libraries Used

- **docx**: Word document generation with professional templates
- **pdfmake**: PDF generation with embedded fonts and bookmarks
- **ajv/ajv-formats**: JSON schema validation for OSCAL compliance
- **js-yaml**: YAML parsing for import functionality

### Architecture Decisions

1. **Browser-based processing**: All export/import happens client-side, maintaining the local-first architecture
2. **Format detection**: Automatic detection from file extension and content analysis
3. **Streaming exports**: Large documents handled efficiently without blocking UI
4. **Validation layers**: Schema validation + business rule validation for comprehensive checks

### Code Quality

- All TypeScript strict mode compliant
- Prettier formatting enforced
- Full type definitions for OSCAL structures
- Comprehensive error handling with user-friendly messages

---

## Challenges & Resolutions

### 1. pdfmake Font Loading

**Issue:** pdfmake vfs font import failing
**Resolution:** Changed from `pdfFonts.pdfMake.vfs` to named import `import { vfs } from 'pdfmake/build/vfs_fonts'`

### 2. Parser Type Mismatches

**Issue:** Multiple type errors in OSCAL parser (wrong enum values, missing required fields)
**Resolution:** Rewrote parser with correct type mappings:

- `ImplementationStatus` uses 'NOT_STARTED' not 'NOT_IMPLEMENTED'
- `Baseline` uses 'LOW'/'MODERATE'/'HIGH' not 'NIST_LOW'
- Added required fields like `createdAt`, `updatedAt`, `selectedTools`

### 3. SspContext Import Method

**Issue:** `saveProject` method didn't exist for imports
**Resolution:** Added new `importProject` method that saves and dispatches `ADD_PROJECT` action
